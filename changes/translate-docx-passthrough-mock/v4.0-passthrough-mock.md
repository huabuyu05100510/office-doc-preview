# v4.0 翻译双栏对照 — DOCX/PDF 源文档 Mock（保留原格式）

> 日期：2026-06-22
> 模型：claude-sonnet-4-6
> 状态：✅ 实现完成 + TDD 全绿 + E2E 待运行

## Context（用户需求）

用户参考 **翻译狗 fanyigou.com** 的 DOCX 翻译流程：

> "翻译完成之后应该 word 文档 但是为了显示呢 先转成 PDF 再转图片显示 翻译是要保留原格式的"

随后简化：

> "翻译你可以先不实现 都用源文档 mock"

**v3.1 的根本问题**：译文包成"合成 A4 HTML"丢掉了所有原 DOCX 排版（图片、表格、字体、页眉页脚）。

**v4.0 MVP**：
- 跳过真实翻译（identity mock）
- 右 cell 显示源文档同一张图（与左 cell 完全一致）
- 原格式天然保留
- 等真实翻译 API 接好，把 mock 替换为真实翻译，渲染管线不变

---

## 整体方案

### 管线对比

```
v3.1 'synthetic'（丢格式）           v4.0 'passthrough'（保留格式）
─────────────────                   ─────────────────
DOCX 上传                            DOCX 上传
  ↓                                   ↓
soffice → PDF                        soffice → PDF
  ↓                                   ↓
PDFium → 源 PNG + v4 文字层          PDFium → 源 PNG + v4 文字层
  ↓                                   ↓
extractTaskText                      extractTaskText
  ↓                                   ↓
translate + paginateText（人造页）    translate = identity mock（按 task.pages 原页结构）
  ↓                                   ↓
buildTranslatedHtml（合成 A4）        跳过：直接复用源 page.png
  ↓                                   ↓
soffice → 译文 PDF（第二次转换）      （无 soffice 第二次转换）
  ↓                                   ↓
PDFium → 译文 PNG + 文字层 v5         PDFium 从源 PDF 提 runs → v6 fullDoc 文字层
```

### 关键设计

| 决策 | 选择 | 理由 |
|---|---|---|
| 翻译 mock | **identity 1:1**（srcStart=srcEnd=0..N） | per-char 粒度，hover 联动单字高亮 |
| DOCX/PDF 右 cell | **直接复用源 page.png** | 原格式天然保留（同一张图同一份文字层） |
| txt/md 右 cell | **保持 v3.1 合成 A4** | 简单文本无格式；后续可同样改为复用 |
| charMap | **fullDoc global offset** | 真实翻译是 fullDoc 一次过；按页切 charMap 后续不兼容 |
| text-layer 版本 | **v6 = fullDoc global char-level** | 兼容 v5（per-page）；旧版自动重生 |
| 缓存 key | **`<strategy>:<taskId>:<page>:<lang>`** | passthrough 与 synthetic 互不污染 |

## 关键技术点

### 1. 缓存 key 命名空间

```js
// translate-render.mjs
const key = strategy === 'passthrough'
  ? `passthrough:${taskId}:${pageNum}:${targetLang}`
  : `synthetic:${taskId}:${pageNum}:${targetLang}`
```

避免 passthrough 与 synthetic 的缓存条目互相覆盖。

### 2. 磁盘缓存版本嗅探

旧版（v5 含 charMap、v4 run-level）自动失效：

```js
if (fs.existsSync(cacheHtml)) {
  const head = fs.readFileSync(cacheHtml, 'utf-8').slice(0, 256)
  if (!head.includes('data-pdfium="6"')) {
    fs.unlinkSync(cacheHtml)  // 删旧版，重生 v6
  }
}
```

### 3. per-char charMap（identity 模式）

```js
// translate.mjs buildIdentityPagesFromTask
const charMap = chars.map((_, ci) => ({
  srcStart: ci, srcEnd: ci + 1,
  tgtStart: ci, tgtEnd: ci + 1,
}))
```

per-char 而非单段，让 hover 联动粒度 = 单字（更好的 UX）。

### 4. v6 文字层（fullDoc global charMap + pageSlice）

```js
// pdfium-text-layer.mjs buildFullDocTextLayer
const pageSlice = { pageCharStart: 0, pageCharEnd: tgtChars.length }
const textHtml = buildFullDocTextLayer(runs, pageW, pageH, fullTgt, globalCharMap, pageSlice)
```

支持 fullDoc 一次过 + 按页切分（未来真实翻译 API 接入时，`globalCharMap` 是 fullDoc 全局 offset，`pageSlice` 是该页对应的字符范围）。

### 5. 端点透传 + 响应头

```js
// router.mjs
res.setHeader('X-Translate-Strategy', strategy || 'synthetic')
res.setHeader('X-Translate-Engine', engine)
```

前端 / 调试工具可直接通过响应头判断走的哪条管线。
