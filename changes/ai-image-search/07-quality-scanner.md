# 07 — Quality Scanner(图片质量雷达)

> **模型声明**:claude-sonnet-4-6
> **调研日期**:2026-07-01
> **核心定位**:用户上传一张手机拍的合同照片 → 系统自动在 6 个维度(倾斜 / 模糊 / 亮度 / 阴影 / 摩尔纹 / 反光)上打分 → 给"低质量"标签 + 一键"AI 增强"(自动 deskew / 透视矫正 / 去阴影 / 增强对比度 / 灰度 / 黑白)
> **对标产品**:Adobe Scan(自动 deskew + 透视矫正 + 增强,最强对标)/ CamScanner 增强 5 档 / 华为智慧视觉文档扫描 / 扫描全能王(CS 全能扫描王)/ 百度网盘图搜(质量评分)/ Microsoft Lens / ABBYY FineReader 图像增强
> **数据来源说明**:本环境 WebSearch / WebFetch 工具持续返回 API 错误(400 / 域名校验失败),所有"业界案例"基于截至 2026-01 的模型知识 + 本项目 `MEMORY.md` / `changes/ai-block-polish-design/` 已沉淀的设计规范。具体数字/截图建议下游在能联网的环境下复跑核验。
> **本报告纯只读**,未修改任何代码文件。

## 0. 用户故事

**主用户场景**(高频):
小王用手机拍了一份纸质合同(20 页),拍完才发现光线偏暗、有阴影、纸面微皱,3 张是歪的。她把图片拖到本应用 → 系统 1 秒内给出"质量雷达图"——6 个维度一眼可见,总评分 62/100,标记为"低质量"。系统提示"建议 AI 增强"并一键应用 5 档增强(自动 deskew + 去阴影 + 增强对比度)→ 处理后评分跳到 91 → 自动跑 OCR(下一子模式)准确率从 73% 跃升到 96%。

**次用户场景**(中频):
小红拍了一张白板照片,远处反光导致右上角大片反光,她想"只处理反光区域不破坏其它部分" → 进入"局部增强"模式,在反光区域画框 → AI 仅对框内做反光去除 → 局部预览对比 → 一键应用。

**探索用户场景**(低频):
老张想批量检查 50 张历史照片哪些需要增强 → 进入"批量质检"模式 → 50 张图片并行评分 → 列表显示评分 + 红旗低质量图 → 勾选需要增强的 → 一键批量 AI 增强。

## 1. 行业最佳实践

### 1.1 Adobe Scan(移动端最强对标)

Adobe Scan 在拍照流程完成后,**总是先过一遍图像质量评估再 OCR**——评估用 4 个维度(倾斜 / 模糊 / 光线 / 文档边缘完整性),每个维度有红黄绿三色指示。**杀手锏**:实时取景器中提示"光线偏暗" / "文字太模糊" / "请将文档四角对齐取景框",用户拍前就拍到清晰照片。识别前若评分低,自动弹"AI Enhance"按钮(占位 32px 圆角,渐变紫红 #FA0F00 → #FF6F00)。视觉风格:紫红强调 + 白底 + 大圆角 + 卡片阴影 0/4/16。**核心启发**:质量评估应**前置到拍照时**(实时取景)+ **后置到识别前**(雷达图),双重防线。

### 1.2 CamScanner(增强 5 档)

CamScanner 的增强是**5 档 toggle**,从弱到强:原图 / 增强 / 灰度 / 黑白 / 增强对比度。每档可独立预览,左右双栏对比("Before / After"),滑块可调"增强强度 0-100"。**杀手锏**:增强前后对比 slider——一条竖线分割线,鼠标拖拽切换左右显示,实时看到差异。**批量应用**支持 50 张同时增强。**核心启发**:5 档 toggle + 强度 slider 是行业成熟范式,本项目应直接复用。

### 1.3 华为智慧视觉文档扫描

华为在 HarmonyOS 4 起内置文档扫描,核心亮点是**「智能识别文档边界 + 自动裁剪 + 透视矫正」**。拍完一张歪的照片,系统识别 4 个角点并实时显示 4 个角的绿色圆点(可拖拽微调),点确认后自动透视变换到正视矩形。**杀手锏**:4 个角点可手动拖拽微调(适用于系统识别失败时),拖拽时实时显示变换预览。**核心启发**:质量扫描与"4 点透视"是文档扫描的灵魂动作,本项目应把 4 点手动调整作为"高级模式"留给用户。

### 1.4 扫描全能王(CS 全能扫描王)

国内 App Store 评分最高的扫描 App。核心差异点是**「阴影去除」**——他们的专利算法专门针对手机拍文档的"手部阴影",检测阴影区域并做局部提亮 + 阴影方向模糊。**杀手锏**:增强结果分**自动 / 普通 / 灰度 / 黑白 / 增强** 5 档,每档有缩略图预览(120x180)排列在底部,点击切换。**核心启发**:"阴影"是手机拍文档第一痛点,本项目应把阴影评分作为单独维度(独立于"亮度")。

### 1.5 ABBYY FineReader 图像增强

桌面 OCR 老牌工业典范,图像增强面板是**左侧 8 个 toggle + 右侧预览**:Auto Brightness / Auto Contrast / Auto Deskew / Auto Rotate / Despeckle / Remove Background / Smooth / Sharpen。每个 toggle 独立开关 + 实时预览。**杀手锏**:每次 toggle 变化后,**0.5s 防抖后实时跑预览**(用 Web Worker 避免阻塞 UI),左侧 toggle 栏右侧显示"当前应用了 X / 8 个增强"。**核心启发**:8 个 toggle 模式对消费级过重,本项目应收敛到 5 档 + 滑块,更轻量。

### 1.6 百度网盘图搜质量评分

百度网盘 App 上传图片后,在缩略图右下角叠加一个**"图片质量分"小角标**(绿色 √ / 黄色 ! / 红色 ✗),点开看 4 维度雷达图。**杀手锏**:**离线评估**——上传前在客户端(JS / iOS)做初步评分,避免低质量图占用服务器 OCR 配额。**核心启发**:前端 WebAssembly 实现 6 维度评估是技术亮点(也是本项目的差异化优势)。

### 1.7 Microsoft Lens(微软智能镜头)

Lobe 系列移动 App,白板 / 文档 / 名片三种模式自动适配不同增强参数。**杀手锏**:**「拍照引导 AR 框」**——实时识别文档边界,在屏幕上显示 4 个角点 + 透视网格,用户对齐后自动拍。**核心启发**:本项目虽然不重拍照,但"拍照建议"浮窗可借鉴。

### 1.8 主流范式总结

## 2. 亮点挖掘(≥ 8 条)

### 亮点 1:6 维度质量雷达图(蜘蛛图)— 自创
**产品出处**:百度网盘图搜 4 维度雷达图 + Adobe Scan 4 色指示灯 + 行业 Radar Chart 设计范式。
**描述**:页面正中一个 200x200 的六边形雷达图,6 个轴从中心向外辐射,每轴代表一个质量维度(倾斜 / 模糊 / 亮度 / 阴影 / 摩尔纹 / 反光)。轴上有一个红→黄→绿渐变线(0-100 分),用户在中心点看到的整体"形状"一眼判断质量——正六边形(60+ 全绿)= 优秀;有尖角凹陷 = 某维度严重短板。**视觉差异化**:雷达图配色用 semantic token `--color-status-green / -amber / -red`,与全局设计语言一致(不引入新色板)。
**交互**:鼠标 hover 任一维度轴 → 该维度评分卡在右侧高亮(黄色描边 2px,200ms ease-out)+ 雷达图对应轴端点放大 1.2x(200ms scale)。点击维度 → 弹出该维度的"详细解释 + 修复建议"popover。
**技术**:SVG + Framer Motion 路径动画(0 分 → 实际分沿轴向画线,300ms ease-out)。

### 亮点 2:拍照建议实时浮窗 — 借鉴 Adobe Scan / 华为
**产品出处**:Adobe Scan 拍照引导 + 华为智慧视觉 AR 框 + Microsoft Lens AR 网格。
**描述**:实时取景器(若用户开启摄像头)或上传预览(若上传已有图)上叠加半透明黑底白字浮窗,根据实时质量评分动态显示:
- 倾斜 > 5° → "📐 图片倾斜 3.2°,请扶正相机"
- 模糊 > 0.3 → "🌫️ 图片模糊,请稳住手机或点击对焦"
- 亮度 < 30 → "💡 光线偏暗,请到亮处拍摄或开启闪光灯"
- 亮度 > 85 → "☀️ 过曝,请避开直射光"
- 阴影 > 40% → "👋 有手部阴影,请双手悬空拍摄"
- 反光 > 30% → "✨ 检测到反光,请调整角度避开光源"
- 摩尔纹 > 0.4 → "📺 检测到屏幕纹理,请拍纸面而非屏幕"
**交互**:浮窗在画面顶部居中,自动 4s 后渐隐(200ms),有新警告时重新浮现。**关键**:必须非阻塞,可穿透点击底层。
**技术**:WebRTC getUserMedia + 实时评分(每 500ms 一次,Web Worker)。

### 亮点 3:AI 增强 5 档 + 强度 slider — 借鉴 CamScanner
**产品出处**:CamScanner 增强 5 档 + ABBYY 8 toggle + 扫描全能王 5 档。
**描述**:底部 toolbar 一行 5 个 chip,每个 chip 是 100x140 的缩略图(原图微缩处理后),chip 上方文字"原图 / 增强 / 灰度 / 黑白 / 增强对比度",下方"处理时长 / 评分变化"。当前档 chip 加 2px `--color-brand` 描边 + 阴影 0/4/12。**强度 slider**:5 档下方一条 0-100 的横向 slider(200x8 圆角),默认 60,实时刷新预览。
**交互**:点击 chip 切换 → 右侧画布 300ms 渐变到新档预览;拖动 slider → 0.5s 防抖后刷新预览(用 Web Worker 跑 Canvas 像素处理);长按 chip 弹出"该档详细说明"popover(包含算法简介 + 适用场景)。
**技术**:Canvas ImageData + Web Worker(主线程不卡),处理后用 toDataURL 输出预览。

### 亮点 4:4 点透视矫正(高级模式)— 借鉴华为 / Adobe Scan
**产品出处**:华为智慧视觉 4 点拖拽 + Adobe Scan 透视变换。
**描述**:在主视图右上角有"高级模式"按钮,点开后画布切换为"4 点编辑"模式:图片 4 角各一个绿色圆点(12px 直径),用户拖拽角点到文档真实角点。拖拽时实时显示透视变换预览(半透明叠加在原图上)。"重置"按钮恢复初始识别角点;"确认"按钮应用变换。
**交互**:拖拽角点时显示"当前坐标 (x, y) / 距离初始 (dx, dy) px";"确认"后 300ms 渐变回到正常视图,质量雷达图自动重算。
**技术**:Canvas + Perspective Transform 矩阵(自实现 8 参数 homography 或引入 `@kitware/vtk.js`);评估后所有 6 维度评分重新计算。

### 亮点 5:局部增强(框选局部)— 借鉴扫描全能王
**产品出处**:扫描全能王"局部去阴影"+ Photoshop Generative Fill 选区。
**描述**:在"增强"档位下,有"局部增强"按钮,点开后画布变为"框选模式"——用户拖拽框选一个矩形区域,系统**仅对该区域**应用增强(去阴影 / 增强对比度 / 去反光),其它区域保持不变。**杀手锏**:多次框选可叠加(每框单独一次增强操作,栈式记录,可撤销)。
**交互**:鼠标拖拽画框 → 松开后 200ms 显示该区域的处理预览(原图 vs 处理后)→ 点"✓ 应用"或"✗ 取消";最多支持 5 个框同时存在(过多会卡顿)。
**技术**:Canvas getImageData 子区域 → 局部 ImageData 处理 → putImageData 回写。

### 亮点 6:批量质检 + 批量增强 — 借鉴 CamScanner / WPS
**产品出处**:CamScanner 批量 + WPS 图片转 Word 50 张并发。
**描述**:页面右上角"批量质检"按钮,点开后切换到"队列模式":左侧 240px 队列列表(每行 64x64 缩略图 + 文件名 + 评分条),右侧大画布显示当前选中图片。底部"批量增强"按钮 + "导出所有"按钮。
**交互**:进入批量模式后,系统**并行 3 个**评分(可调 1-5),每完成一张自动追加到列表(瀑布流,新条目高亮 1s 黄底)。勾选多张 → "批量增强" → 进度条 + 预计剩余时间。
**技术**:复用 `useImageBatch` hook(已在仓库)+ Promise.all 并发控制 + 队列状态在 zustand store。

### 亮点 7:质量维度详情 popover(算法透明)— 自创
**产品出处**:学术论文 / Adobe Scan 的"为什么这个分数?" + Google AI Explainability。
**描述**:雷达图每轴或评分卡"?"按钮,点开后弹出 320x280 的 popover,包含:
- 维度名称 + 图标(emoji 16px)
- 评分数值 + 颜色徽章(红黄绿)
- **算法说明**(1-2 句话通俗版,例如"通过计算图像边缘的平均角度与水平方向的偏差")
- **修复建议**(3 条,例如"建议使用 AI 增强 → 自动 deskew")
- **可视化小图**:该维度的诊断图(倾斜维度显示检测到的水平线;模糊维度显示边缘强度热力图;亮度维度显示亮度直方图)
**核心价值**:**让 AI 评分可解释**,建立用户信任。这是技术产品的"深度感"。
**技术**:Canvas 子图渲染,作为 base64 inline PNG。

### 亮点 8:处理历史 + 撤销栈(50 步)— 借鉴 Adobe Scan
**产品出处**:Adobe Scan 处理历史 + Photoshop 历史记录面板 + Figma 版本历史。
**描述**:顶部 toolbar 右侧"历史"按钮,点开下拉显示最近 50 步操作记录(每条 240x40:操作名 + 缩略图 + 时间),点任一条回滚到该步骤。**底层**:每次"AI 增强"或"4 点矫正"或"局部增强"都 push 一个 state snapshot 到内存栈,占用内存约 5MB / 步(200x200 Canvas ImageData 缩略图),50 步上限自动滚动覆盖。
**交互**:Cmd+Z / Cmd+Shift+Z 撤销 / 重做;鼠标 hover 历史项显示"完整预览"(原图 vs 当前 vs 该步)。
**技术**:zundo middleware(zustand 时间旅行)+ ImageBitmap 压缩存储。

### 亮点 9:增强前后对比 slider(Before/After)— 借鉴 CamScanner
**产品出处**:CamScanner 对比分割线 + Photoshop 历史刷 + Figma 历史版本对比。
**描述**:页面底部一条 240x40 的"对比工具条",中央一条可拖拽的竖直分割线(2px 白底 + 12px 圆形拖拽手柄),分割线**左侧显示原图**,**右侧显示当前增强结果**。拖拽手柄在 0-100% 区间移动,实时切换显示区域。
**杀手锏**:**双指捏合手势**(移动端)+ 鼠标拖拽(桌面端)统一交互。键盘左右箭头键也可移动分割线。
**技术**:两个 Canvas 叠加(原图在下,处理后在上) + clip-path 实时裁剪上层。

### 亮点 10:质量评分 + OCR 联动(预测准确率)— 自创
**产品出处**:Google AI "预测模型置信度"+ 百度 iOCR 识别质量总览。
**描述**:评分卡底部一行小字"📊 预计 OCR 准确率 73%",数字根据当前评分动态计算(用线性回归 / 简单查表)。用户看到 73% → 知道"如果直接 OCR 会丢 27% 内容" → 强烈驱动他去点 AI 增强 → 增强后看到"📊 预计 OCR 准确率 96%" + 实测 OCR 后准确率徽章验证。
**杀手锏**:**评分 → OCR 准确率的可解释映射**(用户能"看见"质量的价值)。
**技术**:后端 `/api/quality/predict-ocr` 接口(输入 6 维度分数,输出预测 OCR 准确率)+ 实测后用 `/api/ocr/recognize` 的 `X-OCR-Confidence` 校验预测偏差。

### 亮点 11(可选):自动重拍建议(仅移动端)
**产品出处**:Adobe Scan 拍照引导 + 华为 AR 网格。
**描述**:若用户在拍照模式,系统实时评分 < 60 时,在画面顶部红色横幅"📷 建议重新拍摄,当前评分 42"。点横幅 → 弹出"重拍 vs 强行使用"选择;选"强行使用"仍可继续,但加红色低质量标记。
**技术**:WebRTC + 实时评分 + 评分阈值触发。

### 亮点 12(可选):API 调用量节省(离线评分)
**产品出处**:百度网盘图搜客户端评分。
**描述**:前端 WebAssembly 实现 6 维度评分,避免低质量图占用服务器 OCR 配额。**核心价值**:**成本节省 + 隐私保护**(图不出端)。
**技术**:Rust 编译 WASM(`wasm-pack` + `image` crate)做像素级评估,~80KB 大小,加载后 < 500ms 评估一张 4K 图。

## 4. 关键交互流(用户故事 + 步骤)

### 流 1:单图 AI 增强(主流程)

**用户故事**:作为合同扫描员,我想上传一张手机拍的照片,系统自动评分并提示增强,一键应用后跑 OCR。

**步骤**:
1. 用户点击顶部"上传"按钮 → 文件选择对话框(支持 jpg/png/bmp/webp/heic)
2. 用户选择文件 → 前端 Web Worker 跑 6 维度评分(预计 800ms)
3. 评分完成 → 主视图渐入原图(300ms ease-out)+ 右侧评分卡渐入(200ms delay)
4. 综合评分 < 60 → 自动弹"建议 AI 增强"toast + 主视图加"✨ AI 增强"浮动按钮(2s 后渐隐)
5. 用户点击"AI 增强" → 5 档 chip 高亮"增强"档(2px 描边 200ms)+ 主画布 300ms 渐变到增强结果
6. 评分重新计算 → 雷达图重新绘制(路径动画 300ms)+ 综合评分跳到 91
7. toast:"✅ 已 AI 增强 · 评分 62 → 91 · 预计 OCR 准确率 73% → 96%"
8. 右侧评分卡底部"一键 AI 增强"按钮变成"开始 OCR 识别"(复用 OCRPage)
9. 用户点击"开始 OCR" → 跳转或模态显示 OCR 结果,准确率徽章显示 96%

**可观测埋点**:每个步骤都有 `console.log('[quality ISO]', event)` + response header `X-Quality-Score-After`。

### 流 2:实时拍照引导(可选)

**用户故事**:作为拍照小白,我想实时看到"现在拍的角度好不好",系统给出提示。

**步骤**:
1. 用户点击"拍照"按钮 → 浏览器请求摄像头权限 → 实时预览(15fps)
2. 每 500ms 跑一次 Web Worker 评分(降低频率避免耗电)
3. 评分 < 60 → 顶部浮窗显示警告(2-4 条,4s 后渐隐)
4. 用户按拍照按钮 → 截取当前帧 → 跳转到"单图评分模式"继续流程 1

### 流 3:批量质检(50 张)

**用户故事**:作为档案管理员,我想批量检查 50 张扫描件哪些需要重拍或增强。

**步骤**:
1. 用户点击"批量"按钮 → 文件多选(支持 50 张)
2. 进入批量模式 → 队列列表显示 50 个"等待"占位项(灰色占位符)
3. 系统并行 3 个评分 Promise(可调 1-5),完成的项替换为实际缩略图 + 评分
4. 进度条实时更新(已完成 / 50),预计剩余时间动态计算
5. 完成后自动滚动到第一个低质量图(评分 < 60)
6. 用户勾选若干低质量图(默认全选)→ 点"批量增强"
7. 系统串行/并行增强(同 3 并发),每张完成后更新评分
8. 完成 → toast"✅ 50 张已完成,38 张已增强,平均评分 71 → 89"
9. 用户点"导出" → 打包下载 50 张处理后图片(zip)

### 流 4:4 点透视矫正(高级)

**用户故事**:作为扫描老手,我发现系统自动识别的角点不准,想手动调整。

**步骤**:
1. 用户在主视图点"📐 4 点矫正" → 画布切换到编辑模式
2. 4 个角点显示绿色圆点(12px),用户拖拽到文档真实角点
3. 拖拽时实时显示透视变换预览(半透明叠加)
4. 点"确认" → 300ms 渐变回正常视图,评分重新计算
5. 点"重置" → 角点回到系统初始识别位置

### 流 5:局部增强(去阴影)

**用户故事**:我只想处理图片阴影区域,其它部分保持原样。

**步骤**:
1. 用户选择"增强"档位 → 出现"🎯 局部增强"按钮(仅增强档可用)
2. 点击"局部增强" → 画布变为框选模式(光标变 crosshair)
3. 鼠标拖拽框选反光区域 → 松开后 200ms 显示处理预览
4. 显示"原图 vs 处理后"对比(框内)+ 其它区域保持原图
5. 用户点"✓ 应用"或"✗ 取消"
6. 应用后该框加紫色描边,质量雷达图阴影维度刷新

### 流 6:历史回滚

**用户故事**:我不小心应用了错误增强,想撤销到上一步。

**步骤**:
1. 用户按 Cmd+Z(或点工具栏"↩ 撤销") → 主画布 200ms 渐变到上一步状态
2. toast:"↩ 已撤销到 5s 前的 4 点矫正"
3. 用户可继续撤销或点"↪ 重做"(Cmd+Shift+Z)
4. 用户点"📜 历史" → 弹出历史面板,可点任意步直接跳转

## 5. 动效规范

| 动作 | 时长 | Easing | 实现 |
|---|---|---|---|
| 主画布渐入(上传后) | 300ms | ease-out | opacity 0 → 1, scale 0.95 → 1 |
| 评分卡渐入 | 200ms (delay 100ms) | ease-out | opacity 0 → 1, translateY 8 → 0 |
| 雷达图路径动画 | 300ms | ease-out | SVG pathLength 0 → 1 + stroke-dashoffset |
| 雷达图端点放大(hover) | 200ms | ease-out | scale 1 → 1.2 |
| 5 档 chip 切换描边 | 200ms | ease-out | stroke-width 0 → 2px |
| 主画布切换档位预览 | 300ms | ease-in-out | cross-fade(不滑动,避免眩晕) |
| 对比分割线拖拽 | 实时 (60fps) | linear | clip-path 实时裁剪 |
| 拍照建议浮窗渐隐 | 200ms (delay 4s) | ease-in | opacity 1 → 0, translateY 0 → -8 |
| 4 点角点拖拽 | 实时 (60fps) | linear | transform 跟随鼠标 |
| 局部框选 | 实时 (60fps) | linear | 框 width/height 跟随 |
| 历史面板展开 | 200ms | ease-out | height 0 → auto + opacity |
| Toast 弹出 | 200ms (delay 100ms) | spring (stiffness 200, damping 20) | translateY -8 → 0 + opacity |
| Toast 消失 | 200ms (delay 3s) | ease-in | opacity 1 → 0 |
| 批量进度条更新 | 200ms | ease-out | width 百分比变化 |
| 批量队列新条目高亮 | 1s | ease-out → ease-in | background-color 灰 → 黄 → 灰 |

**统一规范**:全局遵循 Material easing `[0.4, 0, 0.2, 1]`,从 `web/src/motion/primitives/` 复用 Hover / Press / PageTransition 原语。所有动效读 `<html data-motion="on|off">`,默认 off(无障碍)。

**特殊动效**:
- 雷达图首次绘制时,从中心点向外辐射 6 条线 + 端点依次亮起(stagger 50ms),有"扫描"仪式感
- 综合评分数字滚动(0 → 62,500ms ease-out)
- 5 档缩略图处理完成时,从灰到彩色渐变(opacity 0.3 → 1,300ms)

## 12. 风险与边界

### 12.1 技术风险

1. **WebAssembly 浏览器兼容**:Safari 14+ 已支持,但老 IE / 微信内置浏览器可能不支持,需 server-side fallback。
2. **Canvas 像素处理性能**:4K 图 ImageData 处理可能 1s+,需用 Web Worker + OffscreenCanvas(若可用)。
3. **透视变换算法**:自实现 homography 矩阵计算量大,8 阶方程求解需谨慎,建议引入轻量库(`@kitware/vtk.js` 或自实现)。

### 12.2 产品风险

1. **拍照建议过度打扰**:浮窗频繁弹出可能让用户烦躁,需可关闭 + 学习模式(只在评分 < 30 时提醒)。
2. **5 档增强档位不足 / 过多**:需用户调研后定夺,可考虑"自动模式"基于评分自动选档。
3. **雷达图过度技术化**:普通用户可能看不懂,需 hover 时显示通俗解释。

### 12.3 隐私风险

1. **拍照数据不上传**:WebAssembly 端评分不涉及图片上传,需明确告知用户(隐私徽章)。
2. **EXIF 位置信息**:上传图片可能含 GPS EXIF,需在上传前 strip 或明确提示。
