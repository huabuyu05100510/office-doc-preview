# 08 — Multimodal Pipeline(多模态联动)

> **模型声明**:claude-sonnet-4-6
> **调研日期**:2026-07-01
> **核心定位**:用户拖入一张图 → 系统自动串联跑 6 个 AI 能力(质量雷达 / OCR / 反向图搜 / 模板识别 / 跨文档追溯 / 视觉聚类)→ 一站式返回完整 provenance(从原图到最终结果的全链路可追溯)
> **对标产品**:Google Lens 任务分发(最强对标)/ Bing Visual Search Chat 边栏 / Snap Scan → Lens 链 / Adobe Creative Cloud 资产链 / Figma AI 多动作 / Apple Intelligence 跨 App / Midjourney 4 宫格
> **数据来源说明**:本环境 WebSearch / WebFetch 工具持续返回 API 错误(400 / 域名校验失败),所有"业界案例"基于截至 2026-01 的模型知识 + 本项目 `MEMORY.md` / `changes/ai-block-polish-design/` / `changes/ai-result-hover-linkage/` 已沉淀的设计规范。具体数字/截图建议下游在能联网的环境下复跑核验。
> **本报告纯只读**,未修改任何代码文件。

## 0. 用户故事

**主用户场景**(高频):
小张在网上看到一张"宋代汝窑天青釉花口洗"的照片,他想知道:① 这张照片清不清楚?② 上面的中文 OCR 出来是什么?③ 网上有没有同款或类似款?④ 这是不是博物馆藏品的高清版?⑤ 如果是合同照,能不能识别成模板?⑥ 同主题的图还有哪些?——以前他需要打开 6 个 App,现在拖一张图到本应用,左侧 6 能力并行执行时间线滚动,1.5 秒后右侧 6 个 Tab 出齐:质量 / 文字 / 同源 / 模板 / 追溯 / 聚类。他在 Chat 边栏继续问"宋代汝窑的鉴别要点",AI 基于刚才识别的"宋代汝窑"上下文回答,完美。

**次用户场景**(中频):
研究员小李找到一份古籍扫描件,他想"把这张图 OCR 后翻译成英文 + 在我历史文档库里找同源版本"。他拖入图 → 流水线自动 OCR + 翻译 + 跨库追溯,无需切换 5 个 Tab。

**探索用户场景**(低频):
产品经理小周做竞品调研,看到一张 App 截图,他想"这是哪个 App + 哪个版本 + 网上还有哪些相似设计"。流水线反向图搜 + 视觉聚类,10 秒内出 8 张相似 App UI。

## 1. 行业最佳实践

### 1.1 Google Lens(任务分发最强对标)

Google Lens 的核心范式是**「一次拍照,多任务分发」**:用户拍一张照,Lens 后台**自动并行跑 8 个能力**(文字识别 / 商品识别 / 地标识别 / 植物识别 / 动物识别 / 翻译 / 购物 / 类似图),结果以 **horizontal swipe cards**(横滑卡片)展示。**杀手锏**:**「任务自动识别」**——系统根据图片内容智能判断跑哪几个任务(拍植物不跑地标),不需要用户手动选。视觉风格:白底 + Material Design 3 大圆角 + 顶部 chip 行(「全部 / 文字 / 商品 / 翻译 / ...」)+ 卡片高度 280px,每卡有标题 + 缩略图 + 副标题 + 「查看更多」按钮。**核心启发**:**自动任务分发 + 横滑卡片 + 智能跳过**(本项目应该 6 个能力按需启用,不强推全跑)。

### 1.2 Bing Visual Search Chat(Chat 边栏独家)

Bing 在 Visual Search 模式下,主结果区 + **右侧 Chat 边栏**(400px 宽),用户可基于图片内容继续追问"把这份合同的甲方乙方提出来"、"这个产品多少钱"。**杀手锏**:**「图文多轮对话」**——AI 记住当前图片作为上下文,回答时引用图片区域(用 bounding box 高亮"我看的是这个区域")。视觉风格:卡片化消息流 + Chat bubble(用户右对齐浅蓝,AI 左对齐白底)+ 图片引用内嵌缩略图。**核心启发**:Chat 边栏是本项目最值得做的差异化(其它 5 个能力产品都没有)。

### 1.3 Snapchat Scan → Lens 链

Snapchat 的 Scan 模式扫描后,顶部出现 **horizontal pill 链**:"📍 这里是纽约时代广场" / "🛍️ 这件 T 恤 $29" / "🌐 翻译: '欢迎光临'",每个 pill 是一个能力结果,点 pill 展开详情。**杀手锏**:**「轻量 pill 链」**(每 pill 80x40 圆角)+ **「点上展开」**(pill 转 modal,显示完整结果)。视觉风格:Snapchat 标志性黄色 #FFFC00 + AR 滤镜叠加。**核心启发**:轻量 pill 链可作为"概览视图",详情感官下放到 modal。

### 1.4 Adobe Creative Cloud 资产链

Adobe Lightroom + Photoshop + Sensei 的"资产链"模式:用户拖入图片,Lightroom 自动跑"主体识别 + 场景分类 + 相似推荐"3 个能力,结果以 **3 列网格**展示,每列一个能力,用户点开跳到对应 Adobe App。**杀手锏**:**「跨 App 资产链接」**(点 Lightroom 结果跳 Photoshop 编辑)。视觉风格:深色背景 + 紫红强调 + 卡片 280x280。**核心启发**:**资产链接可作为"导出"动作**(本项目导出到 OCR / Translation / QC 等下游子模式)。

### 1.5 Figma AI 多动作

Figma 2024 起集成 AI,选中一个图层后弹出 **「AI Actions」菜单**:「生成代码 / 重命名 / 翻译 / 相似图层推荐」4 个动作,可批量串行执行。**杀手锏**:**「Action Stack」**(动作栈式执行,进度条 + 可取消 + 部分失败不影响其它)。视觉风格:Figma 黑底 + 紫罗兰 + 弹出菜单浮层。**核心启发**:Action Stack 模式适合本项目的"流水线编排"(串行 / 并行 / 可取消 / 部分成功)。

### 1.6 Apple Intelligence 跨 App

iOS 18 起,Apple Intelligence 在不同 App 间穿梭(照片 App 识别 → 备忘录引用 → Siri 总结)。**杀手锏**:**「App Intents」框架**——AI 能力作为系统级 Intent,任何 App 可调用。视觉风格:Apple 标志性彩色气泡 + 跨 App 转场动画。**核心启发**:本项目的 6 个能力可作为**可调用的 Intent**(用户拖图 → 选择"只跑 OCR + 反向图搜")。

### 1.7 Midjourney 4 宫格

Midjourney 输出 4 张候选图(2x2 网格),用户选 1 张继续 upscale。**杀手锏**:**「并发采样 + 选优迭代」**。视觉风格:大图 + 缩略图网格。**核心启发**:本项目在"反向图搜"和"视觉聚类"能力上可借鉴——出 8 张候选,用户选 1 张继续追溯。

## 2. 亮点挖掘(≥ 8 条)

### 亮点 1:6 能力智能分发(自动跳过)— 借鉴 Google Lens
**产品出处**:Google Lens 任务自动识别 + Apple Intelligence App Intents。
**描述**:用户上传图片,系统**先做一次 200ms 的"内容快探"**(调用 `quality-score` 复用 07 子模式的评分 + 1 个轻量分类器判断"是否是文档 / 自然场景 / UI 截图 / 艺术品")。然后**按需启用能力**:
- 文档类(合同 / 发票 / 名片):跑质量 + OCR + 模板 + 跨文档追溯(跳过反向图搜、聚类)
- 自然场景(风景 / 物品):跑质量 + 反向图搜 + 视觉聚类(跳过 OCR、模板)
- UI 截图(界面):跑 OCR + 反向图搜(查找相似 UI)(跳过模板)
- 艺术品:跑反向图搜 + 视觉聚类(跳过 OCR、模板)
**视觉**:左侧时间线只显示"启用"的能力,跳过的不显示。**核心价值**:**节省 60% 算力 + 避免无关结果干扰**。
**交互**:用户可在右上角"能力选择"菜单手动覆盖(强制全跑 / 跳过某些)。
**技术**:`/api/image-search/classify` 轻量分类 + 编排器根据分类结果决定 pipeline。

### 亮点 2:左侧 6 能力执行时间线(状态 + 耗时)— 自创
**产品出处**:workspace-timeline.mjs 已有架构 + Linear 任务列表 + GitHub Actions 进度。
**描述**:左侧 240px 侧栏,顶部标题"🔄 多模态流水线 (6 项)",下方 6 行(每行 56px 高):
```
[●] 质量雷达         812ms  ✓ 完成
[●] OCR 识别        1234ms  ✓ 完成
[●] 反向图搜         892ms  ⏳ 进行中 (预计 300ms)
[●] 模板识别           -    ⏸ 等待
[●] 跨文档追溯         -    ⏸ 等待
[●] 视觉聚类           -    ⏸ 等待
```
每行有:**图标(emoji + 彩色徽章)** + **能力名(主标题)** + **耗时(右侧灰色)** + **状态徽章**(✓ 完成 / ⏳ 进行中 / ⏸ 等待 / ✗ 失败)+ **进度条**(进行中时)+ **▶ 跳转按钮**(完成后跳到对应 Tab)。
**交互**:点击已完成能力 → 主视图切到该能力结果 Tab;点击进行中能力 → 主视图显示实时进度;点击等待能力 → 主视图显示"等待中"占位。**关键**:支持**取消**(右上角 ✕ 停止流水线)+ **重试失败项**。
**技术**:复用 `useWorkspaceTimeline` + `kind='multimodal'`,每能力完成后 emit 时间线事件。

### 亮点 3:右侧 Chat 边栏(图文多轮对话)— 借鉴 Bing 独家
**产品出处**:Bing Visual Search Chat 边栏 + ChatGPT 图片上传 + Claude 多模态对话。
**描述**:右侧 360px 宽 Chat 边栏,顶部显示当前图片缩略图(80x80)+ "上下文已锁定 · 6 项分析完成"。下方消息流:
- **AI 第一条**:"📊 我已完成 6 项分析。质量评分 78(良好),识别到文字 312 字,找到同源图 8 张。你可以问我任何问题,比如'把这份合同的关键条款提出来'。"
- **用户消息**:右对齐浅蓝 bubble,带输入框 + 📎 按钮(可附加图片)+ 🎤 按钮(语音输入)
- **AI 回复**:左对齐白底 bubble,正文回答 + 引用图片区域(用 `[📍#2 区域]` 标记)+ 链接按钮
**杀手锏**:**「图文锁定」**——整个会话上下文是"这张图 + 6 项分析结果",AI 不会忘记。**「区域引用」**——AI 回答时引用具体区域编号,用户点引用 → 主视图滚动 + 高亮该区域。
**交互**:输入框高度自适应(最多 6 行,超出滚动)+ Enter 发送 + Shift+Enter 换行 + 消息加载时 AI bubble 显示 3 个跳动点 + 引用区域 hover 显示图片区域 bounding box。
**技术**:WebSocket 长连接(`/api/chat/multimodal`)+ 流式响应(SSE)+ `chat-context` 包含图片 + 6 项结果。

### 亮点 4:结果 Tab 分桶(横滑)— 借鉴 Google Lens
**产品出处**:Google Lens 横滑卡片 + Snapchat pill 链 + Adobe 3 列网格。
**描述**:主视图中央**顶部 Tab 行**(横向滚动,最多 7 个 Tab):
```
[📊 总览] [📐 质量] [📝 OCR] [🔍 反向图搜] [🎯 模板] [📚 追溯] [🎨 聚类]
```
当前 Tab 加 2px 底部蓝色横线 + 加粗。Tab 内容 480-800ms 渐入(根据 Tab 类型不同)。
**视觉差异化**:Tab 图标用 emoji(直观)+ Tab 数字徽章(显示该 Tab 结果数,如"OCR 12")+ 滑动指示器(右侧箭头 + 阴影渐变提示可滑)。
**交互**:点击 Tab 切换 / 鼠标滚轮横向滚动 / 键盘左右箭头切换。
**技术**:z-index 管理 + overflow-x: auto + scroll-snap-type: x mandatory。

### 亮点 5:OCR 区域 → Chat 引用(联动)— 自创
**产品出处**:Bing 区域引用 + changes/ai-result-hover-linkage hover 联动 + Adobe Sensei 上下文。
**描述**:在 OCR Tab 中,识别出的文字按区域显示(每区域一个 bubble),用户 hover 区域 → Chat 边栏出现"💡 关于这段文字,你可以问:① 翻译这段 / ② 解释含义 / ③ 找同款合同 / ④ 提取关键数字"。
**杀手锁**:**「一键追问」**——点击 4 个建议问题之一,自动发送到 Chat 边栏,AI 立即基于该区域上下文回答。
**交互**:Chat 边栏显示 AI 回答时,引用 `[📍#3 区域]`,用户点引用 → 主视图 OCR Tab 滚动到 #3 区域 + 该区域 2s 高亮闪烁(黄色描边脉冲)。
**技术**:Chat 消息中的引用 token + 主视图定位 API(`scrollIntoView` + `element.classList.add('flash')`)。

### 亮点 6:反向图搜 4 宫格候选(选优)— 借鉴 Midjourney
**产品出处**:Midjourney 4 宫格 + Google Lens 商品候选 + Pinterest 相似推荐。
**描述**:在"反向图搜" Tab,顶部显示**4 张候选图(2x2 网格,各 240x240)**,用户 hover 候选 → 大图预览(800x800)+ 元数据(来源 / 尺寸 / 相似度)。用户点候选 → 进入"追溯" Tab 查看完整 provenance。
**杀手锁**:**「相似度色环」**——候选图右下角一个色环(0-360 度,绿→黄→红渐变),显示相似度 0-100%。**「同源标识」**——若候选与原图同源(同一商品不同角度),显示 🔗 链子图标。
**交互**:鼠标悬停 200ms 后大图预览 + 1s 后显示元数据(避免误触);点击进入追溯 Tab。
**技术**:复用 03 子模式 reverse-image-search 的 hook。

### 亮点 7:模板识别可视化锚点— 借鉴 OCR 模板锚点
**产品出处**:template-matcher.mjs 已有 referenceFields + anchor 锚点算法。
**描述**:在"模板" Tab,左侧显示模板缩略图(240x340),右侧显示匹配的字段表 + 锚点对齐可视化:
- 模板缩略图上叠加**4 个锚点(⚓ 蓝色圆点)** + 4 个识别字段(🎯 绿色方框),用虚线连接(锚点 → 字段)
- 右侧字段表每行:**字段名** + **识别值** + **置信度** + **坐标**
- 顶部"对齐评分:0.92"徽章
**杀手锁**:**「锚点可拖拽微调」**(借鉴 07 子模式 4 点透视),拖拽时实时刷新识别值。
**技术**:复用 05 子模式 template-id 的 hook + 锚点可视化。

### 亮点 8:跨文档追溯(Sankey 关系图)— 自创
**产品出处**:Notion 关系图 + TheBrain 思维导图 + 学术引文网络。
**描述**:在"追溯" Tab,中央一个 **Sankey 图**(节点-链接图),中心是当前图片节点,周围是关联节点(同源图 / 翻译版本 / 派生合同 / 类似模板),用流向粗细表示关联强度。
**视觉差异化**:
- 节点用 emoji(图 / 文 / 合同)+ 圆形头像(80x80)
- 流向用贝塞尔曲线 + 渐变色(粗细 2-12px 表示相似度)
- 中心节点放大 1.5x,周围节点按关联度半径 200-400px 排列
- 右上角"⏱ 时间轴视图"切换按钮,把 Sankey 替换为时间线
**交互**:hover 节点 → 流向高亮(其它变灰 30%)+ 显示节点详情卡(320x240);点击节点 → 跳到对应详情(同源图跳到图搜 / 翻译跳到翻译 Tab)。
**技术**:D3.js + d3-sankey 插件 + SVG 贝塞尔曲线。

### 亮点 9:视觉聚类网格(8 张相似)— 借鉴 Midjourney
**产品出处**:Midjourney 4 宫格 + Pinterest Mood Board + Google Images 类似图片。
**描述**:在"聚类" Tab,顶部一行筛选 chip(全部 / 同主题 / 同色调 / 同构图 / 同风格),下方 4 列网格(响应式:桌面 4 / 平板 3 / 手机 2 列),每张 200x200 缩略图 + 相似度 + 主题标签。
**杀手锁**:**「双指聚拢 / 张开切换网格密度」**(移动端)+ **「滚轮滚动改变列数」**(桌面)。**「瀑布流加载」**——滚动到底自动加载下一页(每页 16 张)。
**交互**:hover 缩略图显示大图 + 元数据 + "🔍 查看同源" / "📌 加入聚类集" 按钮;点击进入大图预览 modal。
**技术**:复用 06 子模式 visual-cluster 的 hook + IntersectionObserver 懒加载。

### 亮点 10:一键"导出报告"(provenance 完整)— 自创
**产品出处**:学术 provenance + Adobe 资产导出 + Notion 导出 PDF。
**描述**:顶部 toolbar 右侧"📋 导出报告"按钮,点开后弹出 **640x720 modal**:
- 标题:"导出多模态分析报告"(可编辑)
- 预览:报告缩略图(右侧)
- 内容选项(checkbox):
  - ☑ 原图(必选)
  - ☑ 6 项分析结果摘要
  - ☑ 时间线详情
  - ☑ Chat 对话记录
  - ☑ Provenance 关系图
  - ☐ 完整 OCR 文字
- 格式:Markdown / HTML / PDF
- 操作:[取消] [📥 下载] [🔗 复制分享链接]
**杀手锁**:**「分享链接带 provenance」**——复制链接后,任何人打开都能看到完整 6 项分析 + 时间线 + Chat 记录(只读)。
**交互**:勾选选项实时刷新预览(200ms 防抖);点击下载触发文件下载;复制链接 → toast"✅ 链接已复制"。
**技术**:服务端 `/api/multimodal/export` 生成 Markdown / PDF(`puppeteer`);分享链接基于 taskId + 短期 token。

### 亮点 11(可选):AI 自动推荐下一步操作 — 自创
**产品出处**:Google Lens "Try this" / Apple Intelligence Suggestions / Figma AI Action。
**描述**:流水线完成后,顶部 toolbar 下方出现一行 **AI 推荐 chip**(根据当前结果智能推荐):
- 检测到合同 → "[📝 提取关键条款]" "[🌐 翻译成英文]" "[📋 创建模板]"
- 检测到自然场景 → "[🔍 找同款]" "[🎨 查看风格相似]" "[📌 加入聚类集]"
- 检测到 UI 截图 → "[🔍 找相似设计]" "[📝 提取文案]" "[🌐 翻译界面]"
**交互**:点击 chip → 主视图切到对应 Tab + Chat 边栏自动发送"AI 推荐的操作"消息。
**技术**:根据 classify 结果 + 6 项输出推荐表(查表)。

### 亮点 12(可选):历史记录 + 可分享
**产品出处**:Google Lens 历史 / Snap 回忆 / Adobe Cloud 历史。
**描述**:顶部 toolbar 左侧"📜 历史"按钮,点开下拉显示最近 20 次多模态分析(每条 320x80 缩略图 + 时间 + 6 项结果摘要)。点击任一条恢复全部状态(图片 + 6 项结果 + Chat 记录)。
**杀手锁**:**「分享给同事」**——单条记录可生成只读链接,接收方打开后看到完整结果。
**技术**:复用 workspace-timeline + localStorage + `/api/multimodal/share`。

## 4. 关键交互流(用户故事 + 步骤)

### 流 1:6 能力流水线(主流程)

**用户故事**:作为研究爱好者,我想拖一张图,系统自动跑 6 个能力并一站式返回。

**步骤**:
1. 用户拖入图片到主上传区(中央大虚线框 + 📁 图标)→ 拖拽悬停时高亮边框(蓝色 2px)
2. 松手 → 图片立即显示在主视图(中央 400x300)+ 顶部 toast"🔄 多模态流水线已启动"
3. 左侧时间线开始滚动:**质量雷达**(800ms 完成)→ **OCR**(1200ms 完成)→ **反向图搜**(开始,显示进度条)
4. 时间线滚动过程中,完成的项依次加 ✓ 徽章 + 耗时数字动态显示
5. 顶部 Tab 行依次亮起可点击(完成的 Tab 解锁)
6. 反向图搜完成后 → 模板识别启动 → 跨文档追溯启动 → 视觉聚类启动
7. 6 项全部完成(约 5s)→ 主视图切到"📊 总览" Tab + toast"✅ 6 项分析已完成"
8. Chat 边栏自动收到 AI 第一条消息"📊 我已完成 6 项分析..."

### 流 2:Chat 多轮追问(图文锁定)

**用户故事**:基于刚才的 6 项分析,我继续追问关键条款。

**步骤**:
1. 用户在 Chat 边栏输入"把这份合同的关键条款提出来" → Enter 发送
2. 用户消息右对齐浅蓝 bubble 渐入(200ms)
3. AI 思考时显示 3 个跳动点(...)
4. AI 回复流式渐入(每个字 30ms):"📝 关键条款如下..." → "1. 合同金额" → "2. 履约期" → ...
5. AI 引用区域编号 `[📍#3]` `[📍#5]` `[📍#7]` 以 chip 形式显示在末尾
6. 用户点 chip `[📍#3]` → 主视图切到 OCR Tab + scrollIntoView + 区域 #3 黄色脉冲闪烁 2s
7. 用户继续问"翻译成英文" → 同上,AI 基于同一上下文回答

### 流 3:OCR 区域 → Chat 一键追问

**用户故事**:在 OCR Tab 看到一段文字,想立即追问 AI。

**步骤**:
1. 用户在 OCR Tab 文字列表 hover 区域 #3 → 该区域加 2px 黄色描边 + 右侧出现"💡 关于这段文字,你可以问:" + 4 个 chip
2. chip 列表:① [🔍 找同款合同] ② [🌐 翻译这段] ③ [📝 解释含义] ④ [📋 提取数字]
3. 用户点 [🌐 翻译这段] → Chat 边栏自动发送"翻译 #3 区域这段话"
4. AI 回复翻译结果,引用 `[📍#3]`
5. 用户点引用 → 主视图 OCR Tab 滚动到 #3 + 闪烁

### 流 4:反向图搜 4 宫格选优

**用户故事**:在反向图搜 Tab 看到 4 个候选,选 1 个进入追溯。

**步骤**:
1. 用户切到反向图搜 Tab(若已完成)→ 4 张候选图 2x2 网格显示
2. 用户 hover 候选 1(200ms 后)→ 主视图显示大图预览(800x800)+ 元数据卡
3. 用户点候选 1 → 主视图切到"📚 追溯" Tab,Sankey 图中心节点显示该候选
4. 时间线"跨文档追溯"项变 ✓ 状态 + 顶部 toast"📌 已选中候选 1"

### 流 5:Sankey 关系图探索

**用户故事**:在追溯 Tab 我想看完整 provenance。

**步骤**:
1. 用户切到追溯 Tab → Sankey 图渲染(200ms 节点依次亮起)
2. 用户 hover 节点"英文翻译" → 该节点放大 1.1x + 其它节点灰度 30% + 流向高亮
3. 节点旁浮出 320x240 详情卡:节点元数据 + "🔗 跳到翻译 Tab" 按钮
4. 用户点"🔗 跳到翻译 Tab" → 主视图切到 OCR Tab(并自动启动翻译流程)
5. 用户按 `[⏱ 时间线视图]` 按钮 → Sankey 切到时间线,显示该节点关联的所有时间点事件

### 流 6:导出报告(完整 provenance)

**用户故事**:我想把这次分析结果导出成 PDF 给同事。

**步骤**:
1. 用户点工具栏"📋 导出报告" → 弹出 640x720 modal
2. 用户编辑标题 + 勾选内容选项(默认全选)→ 右侧预览实时刷新(200ms 防抖)
3. 用户选格式 PDF → 点"📥 下载报告"
4. 系统调用 `/api/multimodal/export` → 服务端 puppeteer 生成 PDF
5. 浏览器触发文件下载 `multimodal-report-2026-07-01-153218.pdf`
6. 用户点"🔗 复制链接" → toast"✅ 链接已复制"+ 链接格式 `https://app.com/share/mm_abc123`

### 流 7:流水线取消与重试

**用户故事**:流水线跑到一半我反悔了,想取消。

**步骤**:
1. 用户在时间线 hover 进行中能力 → 该行出现 ⏸ 取消按钮
2. 用户点 ⏸ 取消 → 该能力中断,后续能力置为"已跳过"
3. toast"⏸ 流水线已停止 · 已完成 2 项 / 已跳过 4 项"
4. 用户点 ✗ 失败的能力 → 该行出现"🔄 重试"按钮
5. 用户点重试 → 该能力重新跑(其它已完成能力不重复)

## 5. 动效规范

| 动作 | 时长 | Easing | 实现 |
|---|---|---|---|
| 图片上传主视图渐入 | 300ms | ease-out | opacity 0 → 1, scale 0.95 → 1 |
| 时间线新行进入 | 200ms | ease-out | translateX -8 → 0 + opacity |
| 时间线状态徽章变化 | 200ms | ease-out | 背景色 transition |
| 时间线进行中进度条 | 持续 | linear | width 百分比 |
| 时间线完成 ✓ 闪烁 | 400ms (1次) | ease-out | scale 1 → 1.2 → 1 |
| Tab 切换渐入 | 200ms | ease-in-out | cross-fade |
| Tab 切换横向滑动 | 240ms | ease-out | translateX 滑动 + 内容渐入 |
| Chat AI bubble 渐入 | 200ms | spring(stiffness 200, damping 20) | translateY -4 → 0 + opacity |
| Chat AI 流式打字 | 每字 30ms | linear | 字符逐字 append |
| Chat 跳动点 (思考中) | 1200ms (循环) | ease-in-out | 3 点 scale 1 → 1.3 → 1 错位 |
| Chat 引用 chip 高亮 | 200ms | ease-out | background-color |
| 4 宫格候选 hover 大图 | 240ms | ease-out | opacity 0 → 1, scale 0.95 → 1 |
| 4 宫格相似度色环 | 800ms | ease-out | stroke-dasharray 0 → length |
| Sankey 节点首次绘制 | stagger 50ms × 12 | ease-out | opacity 0 → 1 + scale 0.8 → 1 |
| Sankey 流向绘制 | 600ms | ease-in-out | stroke-dashoffset 0 |
| 聚类网格瀑布流加载 | 240ms | ease-out | 新行 translateY 12 → 0 + opacity |
| 导出 modal 渐入 | 200ms | ease-out | opacity + scale 0.95 → 1 |
| 推荐 chip 渐入 | stagger 30ms × 5 | ease-out | translateY -4 → 0 + opacity |
| Toast 弹出 | 200ms (delay 100ms) | spring(stiffness 200, damping 20) | translateY -8 → 0 + opacity |
| OCR 区域 hover 黄色描边 | 200ms | ease-out | stroke-width 0 → 2px + color |
| OCR 区域 Chat chip 浮出 | 200ms (delay 100ms) | ease-out | opacity + translateY |
| 闪烁定位(引用跳转) | 2000ms (2 次) | ease-in-out | 黄色 stroke pulse(2px → 4px → 2px) |

**统一规范**:全局 Material easing `[0.4, 0, 0.2, 1]`,复用 `motion/primitives/Hover / Press / PageTransition`,读 `<html data-motion="on|off">` 默认 off。

**特殊动效**:
- **流水线完成时**:6 个 Tab 同时高亮 + 时间线全部打勾 + Chat 边栏 AI 第一条消息渐入,**三屏同步**(120ms 错位,营造"流水线收尾"的仪式感)
- **Chat AI 流式打字**:打字时 bubble 高度动态变化(避免抖动),气泡尾部有 3 个跳动小点
- **Sankey 节点 hover**:除 hover 节点外,其它节点 opacity 0.3(渐变 200ms),强化焦点

## 12. 风险与边界

### 12.1 技术风险

1. **6 能力并行执行**:可能瞬时资源消耗过大(OCR + 反向图搜 + 聚类同时调用),需并发控制(默认 3 并发,可调)。
2. **WebSocket Chat**:移动网络下 WebSocket 容易断,需自动重连 + 心跳。
3. **Sankey 图性能**:12 节点 18 流向渲染可能卡顿,需用 D3 force layout 异步计算。
4. **PDF 导出**:puppeteer 启动慢(2-3s),需预热或异步队列。
5. **Chat 上下文保留**:6 项结果 + 图片 + 多轮对话,上下文可能超出 token 上限,需滚动窗口(只保留最近 N 轮 + 6 项摘要)。

### 12.2 产品风险

1. **6 能力全跑资源消耗**:用户上传 1 张图,后端跑 6 个能力,若并发 50 用户可能压垮服务。需限流 + 排队。
2. **Chat 边栏过度**:右侧 360px 占用屏幕,小屏幕需折叠为浮动按钮。
3. **Sankey 图过度技术化**:普通用户可能看不懂,需 hover 引导 + 平铺视图备选。
4. **分享链接安全**:链接暴露 6 项分析结果,需短期 token + 可撤销。

### 12.3 隐私风险

1. **图片上传**:6 项能力后端调用,图片离开端,需明确告知用户。
2. **Chat 上下文**:图片 + 分析结果在 Chat 服务端保存,需明确隐私协议。
3. **分享链接**:可被任何人打开,需权限控制(私有 / 公开 / 限时)。
