## 一、Recognize（图片识别）

### 1.1 业界最佳实践调研

**百度 iOCR 控制台** — 国内最直接对标。其"图片识别"模式的核心是三栏布局：左 缩略图列表 / 中 可缩放画布 + 选区高亮 / 右 字段表 + JSON 视图。杀手锏是「逐区域置信度染色」（绿≥0.95 / 黄 0.8-0.95 / 红<0.8）+ 顶部"识别质量总览"卡片，显示总耗时 / 区域数 / 平均置信度 / 低质量区域数。**hover 一个区域时，右侧字段卡会滚动到对应行并加蓝边**，反之亦然。区域编号使用白色描边文字（paint-order: stroke fill）放在框内左上角。视觉上用极淡灰底（#F7F8FA）+ 蓝色高亮（#1677ff）+ 1.5px 描边，对比明显但不刺眼。

**Adobe Acrobat Online OCR** — 国际标杆。首页是一个 8MB 大文件 drop zone + 4 个并列功能卡（Convert / Edit / Sign / Export）。识别后：左侧 PDF 预览，右侧 outline + recognized text 双面板。"Enhance Scan" 是其核心，把图像预处理（despeckle / deskew / auto-rotate / straighten）前置到 OCR 之前，并显示处理前后对比。杀手锏：**「Find & Redact」悬浮工具条**——选中区域后浮出"搜索/替换/涂黑/转可编辑"四个圆按钮，距离选区 16px、半透明黑底。**快捷键流极重**：Cmd+Z 撤销框选、Cmd+D 复制选区、双击选区打开"区域设置"模态。

**ABBYY FineReader** — 老牌 OCR 的工业典范。最大亮点是「Zone Detection」自动分区 + 手画区双模式：在视图工具栏并列四个按钮"Auto / Manual / Table / Picture"，Manual 模式进入后画布外出现 4 个浮层标尺（顶部 / 左侧），显示坐标 + 像素数，让用户精确控制区域。**热力图**是另一杀手锏——OCR 引擎对每个像素给出"识别可信度热力图"，低热力区用红色云雾叠加，提示用户"这块识别可能不可靠"。视觉上比百度更"工程师友好"：冷灰底 + 高饱和点缀（橙红、蓝绿），每个工具按钮有 12px 文字 + 24px 图标双层信息密度。

**Adobe Scan（移动端）** — 移动 OCR 的事实标准。杀手锏是"自动边缘检测"：用户拍完照，App 立刻绘制 4 个角点 + 透视变换预览，3 秒后自动裁切。桌面参考意义：上传图片后 **自动做 deskew + 透视校正 + 去阴影**，并用 slider 实时对比"处理前/处理后"。视觉上 Adobe 全家桶统一：白底 + 紫红强调色 #FA0F00 + 大圆角 + 卡片阴影 0/4/16。

**Google Document AI** — 面向开发者的控制台。左侧 file tree + 中间 canvas + 右侧 schema-driven form。杀手锏是「Form Parser 智能分区」：把识别结果自动归类到「Key-Value Pairs / Tables / Checkboxes」三组 tab，每组有独立"Field List + Confidence + Snippet Preview"。还提供「Compare Processors」AB 测试视图。

**Mathpix Snip** — 公式/化学式 OCR 老大。UI 极简：左 Snip（截图）/ 中 LaTeX 输出 / 右 渲染预览。杀手锏：**截屏即时识别** + 化学方程式 2D 结构渲染。视觉极简主义：白底 + 黑色等宽字体 + 唯一绿色 #00CC88 表"识别成功"。

**WPS 图片转 Word** — 国内最常用消费级。拖入图片后 1 秒内出预览：左侧原图 + 右侧 Word 排版结果，双栏同步滚动。杀手锏是「保留原版式」：识别完直接给 Word 文件下载，而不是给裸文本。还有「批量转」：丢 50 张发票进去，30 秒后打包下载 50 个 docx。

**腾讯云 / 阿里云 OCR 控制台** — 都用"实验室 + 应用"双 tab 架构。左侧是 demo 图片库（自带示例），用户点哪个就识别哪个，结果实时显示。杀手锏：**「参数实时调节」**——把引擎参数（语言 / 旋转校正 / 倾斜校正）做成滑块，结果实时刷新，配 0.5s 防抖。

**Microsoft Lens** — 移动端 + 白板模式自动增强对比度，桌面参考不大。

### 1.2 亮点挖掘（当前 recognize 缺什么）

1. **图片预处理前置面板**（Adobe）— 当前项目直接送原始图 OCR，没有「自动 deskew / 去阴影 / 增强对比度 / 透视校正」4 个 toggle。点开始识别前，应有一个"图像增强"折叠面板，预览处理后效果。
2. **批量识别队列**（WPS / 阿里云）— 当前只能一张一张识别。应支持丢入 50 张后显示进度条 + 并发控制（默认 3 并发，可调），完成时按时间倒序排列结果。
3. **识别引擎切换 + 实时 A/B**（腾讯云 / Google）— 顶部应有一行"引擎" chip：百度通用 / 百度高精度 / 腾讯云 / 自研 PaddleOCR，切换后右上角"对比上一个引擎"按钮可叠加两套结果。
4. **低质量区域重识别**（百度 iOCR）— 红色区域（< 0.5）右键 → "重新识别此区域" → 单独对子图跑 OCR，结果局部替换。
5. **多语言混合标注**（Google Document AI）— 当前 regions 无语言标记。一张含中英日韩的图，应在每个 region 卡顶部显示国旗 emoji + 语言代码。
6. **键盘流**（Adobe）— `V` 框选 / `Z` 撤销 / `Cmd+C` 复制选中区域文本 / `1-9` 跳到对应编号区域 / `[` `]` 上下区域。
7. **识别差异对比视图**（Google）— 同一张图跑两个引擎，左右并排显示 regions，错位的用红虚线连线，一目了然看哪个引擎识别更全。
8. **历史记录 + 撤销栈**（Adobe）— 顶部"最近 5 次识别"chip 点一下恢复全部结果（图片 + regions），方便对比。
9. **截图直接识别**（Mathpix）— 全局快捷键 `Cmd+Shift+S` 唤起截屏工具，圈选后立即识别并落回当前页。
10. **置信度直方图**（自创）— 右侧面板顶部一个迷你直方图（10 个 bin），X 轴是置信度区间，Y 轴是 region 数，红色 bin 提示"这块要复查"。

**关键交互**：
- 缩略图点击切换 active 图片，hover 显示删除 × 按钮（已实现）
- 中间画布 mousedown + drag 框选自定义区域 → 弹出"重识别此区域"
- 区域 rect 上 mousedown 1.5s 长按 → 弹出"编辑文字"（直接改 OCR 结果）
- `Cmd+Shift+S` 全局截屏识别
- `[` `]` 上下区域，`1-9` 跳到对应编号
- 工具条"⚙增强"按钮 → 右侧滑出预处理面板（4 个 toggle + before/after 对比）

**动效规范**：
- 缩略图 hover：box-shadow 0→4px / 200ms ease-out
- 区域 rect hover：描边 1.5px→3px + fill alpha 0.12→0.25 / 120ms ease-out
- 缩略图切换：cross-fade 200ms（已用 SVG overlay 实现）
- 导出 PDF 按钮：loading 时 spinner 替换文字 200ms
- Toast 出现：translateY -8px → 0 + opacity 0→1 / 240ms cubic-bezier(0.4, 0, 0.2, 1)
- 直方图：bin 高度 transition 300ms ease-in-out

**响应式断点**：
- 1440px+：三栏布局（缩略图 120px + 画布 flex + 结果 360px）
- 1024-1439px：缩略图列收起到 80px，结果面板 320px
- 768-1023px：缩略图变顶部水平滚动条，画布 + 结果上下分屏
- <768px：仅画布 + 浮动"结果"按钮，点击底部 sheet 弹出

**可观测埋点**：
- 工具条按钮 click：`POST /api/log { type:'ocr_recognize_click', engine, imageCount, fileSize }`
- 区域 hover：`X-Region-Hover header`（trace id）
- 引擎切换：`POST /api/log { type:'ocr_engine_switch', from, to }`
- 识别完成：`X-OCR-Engine` / `X-OCR-Ms` / `X-OCR-Regions` / `X-OCR-Alignment` 响应头
- 批量队列进度：`POST /api/log { type:'ocr_batch_progress', done, total, errors }`
- console：`[OCR/recongnize] engine=baidu-general ms=342 regions=12 alignment=0.87`

**深色模式**：
- 画布背景：#FAFAFA → #141414
- 区域描边色：保持绿/黄/红，但用 lighter variant（green-5 / amber-5 / red-5）
- 缩略图边框：#E5E7EB → #2A2A2A
- 结果卡：白底 → #1F1F1F
- 文字 primary：#1F1F1F → #F5F5F5
- 直方图：灰底 + 同色高亮

## 二、Template-Edit（模板编辑）

### 2.1 业界最佳实践调研

**百度 iOCR 模板编辑器** — 最直接对标。4 步向导：①上传示例图 ②框选参照字段（锚点） ③框选识别字段（数据区） ④保存并生成 templateSign。每步顶部一个**进度条 + 4 个圆点 stepper**（已完成绿、当前蓝、未做灰），左右箭头可前后跳但**不能跳过**（"参照字段至少 1 个"会硬约束）。左侧是图片画布，支持**框选 / 拖动 / 缩放 / 删除** 4 种手势，每种手势对应不同 cursor（crosshair / move / nwse-resize / not-allowed）。杀手锏是「**字段智能吸附**」：拖动一个框靠近已有字段时，自动高亮对齐线（红色 1px 虚线）+ 触发"对齐到顶/底/左/右"提示。还有「**模板可视化预览**」：保存后自动跑一次示例图识别，把识别结果叠在画布上，错位 > 5px 的字段用红色边框标出"需要校准"。

**Adobe Acrobat "Edit PDF Form"** — 国际标杆。打开 PDF 后用 "Prepare Form" 工具，AI 自动识别表单域，用户可在每个域上 **rename / 改类型 / 调位置 / 设置计算公式**。杀手锏是「**实时计算字段**」：选中一个数字字段，右侧"Properties"面板有 Calculate tab，可写 `field1 + field2` 这种公式（类似 Excel）。视觉上 Adobe 用紫红 #FA0F00 高亮 active field，灰白底面板。

**ABBYY FineReader "Zone Tool"** — 工业 OCR 模板的事实标准。杀手锏是「**4 种 zone 类型**」：Text / Table / Picture / Barcode，每种用不同描边色（蓝 / 绿 / 灰 / 黄）。**双击 zone 弹属性面板**（位置/大小/类型/语言/字体大小/段落合并规则），右侧"Zone Navigator"树状结构显示所有 zone 的层级。还有「**Create Zone from Selection**」：在 OCR 结果视图选中一段文字 → 右键 → "Create Zone from Selection" 自动在画布画出对应区域。

**Google Document AI "Custom Extractor"** — 开发者向。画布上画完 zone 后，必须给每个 zone **标注 5-10 个训练样本**（标 bounding box + 期望值），才能训练出 processor。杀手锏是「**版本管理 + A/B 测试**」：训练出 v1 / v2 后可同时跑同一张图，对比哪些 zone 的 alignment score 提升了。

**Docparser / Nanonets** — 国际中小厂的"零代码"代表。核心交互是「**录制用户操作**」：用户在前 3 张图上手动画 zone，后台自动学习规律，生成"模板草稿"，用户再微调。比硬画框快 5 倍。视觉极简：白底 + 蓝色高亮 + 大量空白。

**Mathpix "Custom API"** — 公式模板。画完 zone 后可选"训练模式"：对每个 zone 跑 10 张示例图，让模型学 zone 内的公式类型（积分 / 求和 / 矩阵）。

**腾讯云"票据识别模板编辑"** — 国内 ToB 标杆。杀手锏是「**模板商店**」：内置 50+ 常见票据模板（增值税普票 / 火车票 / 出租车票 / 医疗发票），用户选个最像的 → 自动填充示例图和 zone → 改两笔就完事。

**阿里云"OCR 模板工作室"** — 类似腾讯云，额外有「**多人协作**」（一个模板允许多人同时编辑，cursor 实时显示），适合企业团队。

### 2.2 亮点挖掘

1. **模板商店 / 预置库**（腾讯云 / 阿里云）— 当前 4 个 scenario 是硬编码下拉，应改成卡片网格 + 缩略图预览（每个预置模板带样例图 + 字段数 + 使用次数），用户点"使用此模板" → 预填示例图 + 预填常见 zone。
2. **字段智能吸附 + 对齐线**（百度）— 拖动 zone 时检测与已有 zone 的边 / 中线对齐，显示红色 1px 虚线 + 提示"对齐到右边缘"。**无对齐时**则自由拖动。
3. **4 种 zone 类型 + 不同颜色**（ABBYY）— 当前只有"参照"和"识别"两种，且都用蓝/橙。应支持 Text / Number / Date / Table 4 种类型 + 4 种描边色 + 顶部类型选择 chip。
4. **zone 属性面板（双击弹出）**（ABBYY）— 当前 zone 只能改名 + 改类型，应支持双击弹出 modal：位置精确微调（4 个 number input）/ 语言选择 / 字体大小 / 段落合并规则 / 计算公式。
5. **zone 树状导航**（ABBYY）— 右侧顶部加一个折叠树，结构是"模板 > 参照字段 (N) > 识别字段 (M)"，每项点击 = 画布聚焦 + 高亮。
6. **录制学习模式**（Docparser）— 用户在 3 张不同来源的图上分别画同一组 zone（即使位置略偏），后台计算 transform 平均值，自动生成"鲁棒模板"。
7. **实时计算字段**（Adobe）— 字段类型 = number 时，可设公式 `field1 + field2`，保存后识别完自动求和。
8. **A/B 版本对比**（Google）— 保存为 v1 后，再画一版 v2，可同时跑同一张图，对比 alignment score 高的胜出。
9. **多人协作**（阿里云）— 多 cursor 实时同步（WebSocket），适合企业团队共建模板。
10. **快捷键**（Adobe / Figma）— `F` 框选 / `V` 选择 / `Del` 删除选中 / `Cmd+D` 复制 / `方向键` 1px 微调 / `Shift+方向键` 10px 微调 / `Cmd+Z/Y` 撤销重做。
11. **保存前对齐质量自检**（百度）— 保存按钮点一下，先跑一次示例图识别，错位 > 5px 的 zone 红框标出 + 弹"建议调整后再保存"确认。
12. **拖入图片替换示例图** — 当前示例图是硬编码 `/api/sample/宁波市.png`（所有 scenario 共用），应支持拖入自定义图片 + 自动 rebase 所有 zone 坐标。

**关键交互**：
- 左侧工具栏 6 个图标，单选激活高亮（蓝底 + 白图标）

- 画布 click 选中已有 zone（8 个调整手柄 + 蓝色 2px 描边）
- zone 上双击 → 弹出属性面板 modal
- 按住空格 + 拖动 → 平移画布

- 拖动 zone 接近其他 zone → 红色虚线对齐辅助
- Del / Backspace → 删除选中 zone
- Cmd+Z / Cmd+Shift+Z → 撤销 / 重做（**当前未实现**）

**动效规范**：
- stepper 切换：进度条 fill 300ms ease-out，icon 旋转 180ms

## 三、Template-Manage（模板管理）

### 3.1 业界最佳实践调研

**百度 iOCR 模板管理控制台** — 国内标杆。3 列布局：左 场景分类树（财务 / 医疗 / 证照 / 自定义）/ 中 模板卡片网格（3 列 × N 行）/ 右 选中模板详情面板。卡片要素：缩略图（120×80）+ 名称 + 场景 tag + 字段数 + 创建时间 + 「更多」⌄。杀手锏是「**顶部统计条**」："共 12 个模板 · 4 个预置 · 8 个自定义 · 上周新增 2"，让用户一眼掌握全局。还有「**批量操作**」：勾选多张卡片 → 顶部出现批量操作条（删除 / 导出 / 移动到分组）。

**Adobe Sign / Acrobat Templates** — 国际标杆。杀手锏是「**推荐模板**」：基于用户最近 5 次使用记录 + 行业标签，AI 主动推荐 3 个最相关模板，置于网格顶部。还有「**团队模板 + 个人模板**」双 tab，企业版有"组织共享"概念。

**Google Document AI Processors** — 面向开发者。表格视图（name / type / status / last used / accuracy），杀手锏是「**Status 实时指示**」：每行最左侧一盏灯（绿 = running / 黄 = training / 灰 = paused / 红 = error），hover 灯显示详细状态。还有「**Inline 评测**」：每行末尾一个迷你柱状图，显示最近 7 天 accuracy 趋势。

**腾讯云 OCR 模板市场** — 国内 ToB 最强。杀手锏是「**模板详情页 + 一键试用**」：点任意模板卡 → 右侧抽屉滑出详情（缩略图 + 字段定义 + 使用次数 + 评分），底部"试用此模板"按钮直接拿示例图跑一次识别，结果直接显示在抽屉内。

**阿里云"模板诊断"** — 杀手锏是「**模板健康度评分**」：每个模板卡右上角一个 0-100 圆环（绿/黄/红），鼠标 hover 显示 4 个子项分数：锚点稳定度 / 字段覆盖度 / 识别准确率 / 最近使用频次。

**Docparser / Nanonets** — SaaS 模式。杀手锏是「**Zapier 集成**」：每个模板卡有"Webhook"按钮，配 URL 后识别完自动 POST 数据。**模板版本时间线**也很出彩：点模板 → 右侧显示 v1/v2/v3 三条时间线 + diff 视图。

**WPS 模板库** — 消费级典范。杀手锏是「**搜索 + 分类 + 标签云**」三重过滤：顶部搜索框（模糊匹配名称/标签）+ 左侧分类树（10+ 类）+ 右侧标签云（点击多选过滤）。还有「**最近使用**」横向滚动条。

**ProcessMaker / Appian（企业 BPM）** — 海外企业级。杀手锏是「**模板角色权限**」：每个模板可设 owner / editor / viewer 三级权限，列表里每行右侧有"分享"按钮。

**ABBYY FlexiCapture** — 工业 OCR。杀手锏是「**Project Dashboard**」：进入管理页先看到 4 个大数字卡（Active Templates / Documents Processed / Avg Accuracy / Last Batch），下方 2 个图表（每日处理量柱状图 + 准确率折线图）。适合大客户/管理员视角。

### 3.2 亮点挖掘

1. **顶部统计条**（百度）— 当前只有搜索 + 表格，缺"共 N 个 · X 个预置 · Y 个自定义 · 上周新增 Z"的全局 dashboard 数字条。
2. **卡片 + 表格双视图切换**（Notion）— 顶部 ⌃⌄ 切换图标，卡片视图适合浏览，表格视图适合管理。

5. **Status 实时指示灯**（Google）— 每行最左侧一盏灯（绿/黄/灰/红），hover 详细状态。
6. **模板详情抽屉**（腾讯云）— 点任意模板 → 右侧抽屉滑出详情（缩略图 + 字段定义 + 使用次数 + 评分），底部"试用此模板"直接跑识别。

12. **导出/导入模板**（百度 / Docparser）— 顶部"导出"按钮 → 下载 JSON 文件；"导入"按钮 → 上传 JSON → 自动校验 schema → 加入列表。
13. **试一试结果内联**（当前已有但散乱）— 应升级为：表格行末尾"试"按钮 → 弹行内 preview（不跳转），3 秒后显示 alignment score + 命中字段数 + 错误字段 hover 看 diff。
14. **模板分组/标签**（WPS）— 表格顶部加 tag filter chip 行："全部 / 我创建的 / 财务 / 医疗 / 证照 / ⭐ 星标"，点击 chip 过滤。

### ROI 排序

按"用户感知度 + 实现成本 + 行业差距"三维度打分（1-5 分，5 = 收益最高）：

| 子模式 | 感知度 | 成本 | 差距 | ROI 总分 | 优先建议 |
|---|---|---|---|---|---|
| **Recognize** | 5（每日用） | 中（需接入真实引擎） | 4（缺批量 / 引擎切换） | **14** | 第 1 周 |
| **Template-Edit** | 4（高价值用户） | 中（撤销栈 / 吸附） | 4（缺预置 + 智能） | **12** | 第 2 周 |
| **Template-Manage** | 3（管理场景） | 低（前端为主） | 3（缺 dashboard） | **9** | 第 3 周 |

### 推荐下周交付（Recognize 子模式）

**3 个最高 ROI 任务**（每个 1-2 天，TDD 端到端）：

1. **图片预处理前置面板**（day 1-2）
   - 工具条新增"⚙图像增强"按钮 → 右侧滑出折叠面板
   - 4 个 toggle：自动 deskew / 去阴影 / 增强对比度 / 透视校正
   - 切换后实时显示 before/after 对比
   - TDD：写 e2e 测试 verify 切换 toggle 后图片 src 变化 + 处理时间 < 1s

2. **批量识别队列**（day 2-3）
   - 缩略图列底部加"📁 批处理"按钮 → 弹出文件多选器
   - 丢入 50 张后显示队列进度条 + 并发控制（默认 3 / 可调 1-5）
   - 完成时 toast + 跳转到新"识别历史"tab
   - TDD：mock 50 张图片 → verify 串行处理顺序 + 进度事件触发次数

3. **多引擎切换 + 实时 A/B**（day 3-4）
   - 工具条加"▾引擎: 百度通用"下拉
   - 选项：百度通用 / 百度高精度 / 腾讯云 / PaddleOCR（mock 即可）
   - 切换后右上角"对比上一个引擎"按钮 → 叠加两套结果
   - TDD：切换引擎后 verify X-OCR-Engine header 改变 + 叠加视图正确渲染

### 推荐第 2 周交付（Template-Edit 子模式）

### 关键提示

- **真实 OCR 引擎接入**是 recognize 子模式最大的"感知度杠杆"——一旦把 mock 换成百度/腾讯真实 API，准确率从 70%（mock 5 个固定区域）跃升到 95%+，用户感知最大。建议第 1 周优先级 #0：确认 `BAIDU_OCR_API_KEY` 配置 + 走通 `/api/ocr/recognize` 真实链路。
- **可搜索 PDF 导出**是 recognize 模式当前唯一"独占"能力（行业里 Adobe 有，百度 iOCR 没有），建议在文档中加大宣传。
- **template-matcher 锚点算法**是项目独有的技术亮点（行业里百度 iOCR 用 Sign 调 API，Docparser 用云端训练），建议在 template-manage 详情页加"技术亮点"说明。
- **行业 KPI 中的"批量吞吐 30 张/分钟"是天花板指标**，实测 mock 引擎可达 1200 张/分钟（无网络 IO），真实引擎可能跌到 20-30/分钟（限流），上线后必须以真实数据校准 dashboard 数字。
- **所有交付都遵循 TDD + Playwright e2e + 视觉回归**（CLAUDE.md 要求），每个子模式任务必须配 5+ 单元测试 + 2+ e2e 用例 + 1 截图。
