## 1. 触发：用户反馈

> **「译文也用源文件mock 并实现字符级对应 hover同时高亮联动」**

v3.0 解决了"右栏和左栏格式统一"问题，但还有两个细节没做好：

1. **译文文本是空的**：v3.0 mock 翻译返回 `[en] <原文>`，用户看不出原文被翻译成了什么实际内容
2. **没有字符级对应**：左 cell 一段"你好世界"对应右 cell 一段"Hello World"，但用户看不出"你"对应"H"、"好"对应"ello"…
3. **没有 hover 联动**：用户在左 cell hover "你"，右 cell 完全没反应 — 体验断裂

## 2. v3.1 设计方案

### 2.1 三个核心数据/能力

| 数据/能力 | 来源 | 作用 |
|---|---|---|
| `charMap: [{srcStart, srcEnd, tgtStart, tgtEnd}]` | `/api/inspect/translate` 响应 pages[].charMap | 字符级对应：源 N 字符 ↔ 译文 M 字符 |
| `data-tgt-idx` / `data-src-idx` 属性 | 文字层 HTML span | 鼠标 hover 时反查 src/tgt 位置 |
| `hoveredSrcIdx` React state | 前端 `TranslationLayout` 组件 | 联动全页高亮的单一真相源（single source of truth）|

### 2.2 数据流

```
┌─────────────────────────────────────────────────────────────┐
│                       后端 (Node.js)                        │
│                                                             │
│  源文本 ──→ mockTranslateWithMap ──→ { target, charMap }    │
│                                              ↓              │
│  PDFium 提取 runs ──→ buildTextLayerWithCharMap             │
│                                              ↓              │
│  HTML: <span data-tgt-idx="0" data-src-idx="0">H</span>     │
│                                                             │
└─────────────────────────────────────────┬───────────────────┘
                                          │
                  /render-text            │
                          ↓               │
┌─────────────────────────────────────────▼───────────────────┐
│                       前端 (React)                          │
│                                                             │
│  左 cell (TextPage)                                         │
│    <span class="ttl-char"                                  │
│          data-src-idx={idx}                                │
│          onMouseEnter={() => setHoveredSrcIdx(idx)}>        │
│      你                                                    │
│    </span>                                                 │
│                                                             │
│  右 cell (TranslatedPage) — 文字层通过 dangerouslySetInnerHTML│
│    <span data-tgt-idx="0" data-src-idx="0">H</span>         │
│      ↑ 通过事件委托 (cellRef.addEventListener)              │
│      ↑ mouseover → 读 data-src-idx → setHoveredSrcIdx(idx)  │
│                                                             │
│  TranslationLayout                                          │
│    [hoveredSrcIdx] state → 传给 TextPage                    │
│      → TextPage 内 char 比较 idx===hoveredSrcIdx?           │
│      → 是则 className += " is-hover"（蓝绿高亮）          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.3 双向联动

| 方向 | 触发 | 处理 |
|---|---|---|
| **左 → 左** | hover 左 cell char | `onMouseEnter` → `setHoveredSrcIdx(idx)` → 同 char 加 `.is-hover` |
| **右 → 左** | hover 右 cell 文字层 span | 事件委托 → 读 `data-src-idx` → `setHoveredSrcIdx(idx)` → 左 cell 对应 char 加 `.is-hover` |
| **左 → 右** | hover 左 cell char | `hoveredSrcIdx` 更新 → CSS 选择器（可扩展） |
| **离开** | mouseleave / mouseout | `setHoveredSrcIdx(null)` → 所有 `.is-hover` 清除 |

## 3. 实施细节

### 3.1 后端：`mockTranslateWithMap`

把 `[en]` 前缀替换成"基于字典的字符级翻译"：

- **优先字典匹配**：尝试最长匹配（max 10 chars），命中后整段输出 + 一条 charMap 段
- **兜底 charFallback**：单字未命中 → 按目标语言做音译/转写（如 `你 → ni`，`好 → hao`，标点 → ASCII 等价）
- **同源不译**：`sourceLang === targetLang` 或源文本已纯 ASCII → 不翻译，charMap 是 1:1
- **支持语言**：zh-CN / en / ja / ko / fr / de / es / ru（mock 字典仅 zh↔en 实现，其余走 charFallback）

```js
// server/src/translate.mjs
export function mockTranslateWithMap(text, targetLang) {
  if (!text) return { target: '', charMap: [] }
  // ... 同源不译 / 英文源不译 早退 ...
  const chars = Array.from(text)
  const dict = MOCK_DICT_ZH_EN
  const target = []
  const charMap = []
  let i = 0, tgtPos = 0
  while (i < chars.length) {
    let matched = null
    const maxLen = Math.min(10, chars.length - i)
    for (let len = maxLen; len >= 1; len--) {
      const key = chars.slice(i, i + len).join('')
      if (dict[key]) { matched = { len, translation: dict[key] }; break }
    }
    if (matched) {
      charMap.push({ srcStart: i, srcEnd: i + matched.len,
                     tgtStart: tgtPos, tgtEnd: tgtPos + matched.translation.length })
      target.push(matched.translation)
      tgtPos += matched.translation.length
      i += matched.len
    } else {
      const ch = chars[i]
      const trans = charFallback(ch, targetLang)
      charMap.push({ srcStart: i, srcEnd: i + 1,
                     tgtStart: tgtPos, tgtEnd: tgtPos + trans.length })
      target.push(trans)
      tgtPos += trans.length
      i += 1
    }
  }
  return { target: target.join(''), charMap }
}
```

### 3.2 后端：`buildTextLayerWithCharMap` (data-pdfium="5")

`pdfium-text-layer.mjs` 新增 API：把 PDFium runs 拆成 **char-level spans**，每个带 `data-tgt-idx` 和 `data-src-idx`：

```js
export function buildTextLayerWithCharMap(runs, pageWidthPx, pageHeightPx, targetText, charMap) {
  const w = pageWidthPx.toFixed(2), h = pageHeightPx.toFixed(2)
  if (!runs.length) return `<div class="pdf-text-layer" data-pdfium="5" data-page-w="${w}" data-page-h="${h}"></div>`

  // 1) 构建 tgt idx → src idx 查找表
  const tgtToSrc = new Array(targetText.length).fill(-1)
  for (const seg of charMap) {
    for (let t = seg.tgtStart; t < seg.tgtEnd; t++) {
      if (t < tgtToSrc.length) tgtToSrc[t] = seg.srcStart  // 全段映射到 srcStart
    }
  }

  // 2) 按 run 顺序拆 char-level span（保留 run 字符位置）
  const spans = []
  let tgtSearchPos = 0
  for (const run of runs) {
    const startPos = targetText.indexOf(run.str, tgtSearchPos)
    if (startPos === -1) { spans.push(runToSpan(run)); continue }
    tgtSearchPos = startPos + run.str.length
    const runChars = Array.from(run.str)
    const charWidth = (run.right - run.left) / runChars.length
    for (let i = 0; i < runChars.length; i++) {
      const tgtIdx = startPos + i
      const srcIdx = tgtToSrc[tgtIdx] ?? -1
      spans.push(charToSpan({
        str: runChars[i],
        left: run.left + i * charWidth,
        right: run.left + (i + 1) * charWidth,
        top: run.top, bottom: run.bottom,
        fontSize: run.fontSize,
        tgtIdx, srcIdx,
      }))
    }
  }
  return `<div class="pdf-text-layer" data-pdfium="5" data-page-w="${w}" data-page-h="${h}">${spans.join('')}</div>`
}
```

**版本号 bump**：`data-pdfium="5"`（之前 v4 是 run-level），触发旧缓存自动重生。

### 3.3 前端：`TextPage` 字符级渲染

把之前按行 `<p>` 改成"每字一 span"：

```tsx
function TextPage({ text, onHoverSrcIdx, hoveredSrcIdx }) {
  const lines = text.split('\n')
  let srcIdx = 0
  return (
    <div className="ttl-page-body">
      {lines.map((line, lineIdx) => {
        const lineStart = srcIdx
        const chars = Array.from(line)
        const lineEls = chars.map((ch, i) => {
          const idx = lineStart + i
          const isHover = hoveredSrcIdx === idx
          return (
            <span key={i}
                  className={`ttl-char${isHover ? ' is-hover' : ''}`}
                  data-src-idx={idx}
                  onMouseEnter={() => onHoverSrcIdx(idx)}
                  onMouseLeave={() => onHoverSrcIdx(null)}>
              {ch}
            </span>
          )
        })
        srcIdx = lineStart + chars.length + (lineIdx < lines.length - 1 ? 1 : 0)
        return <p key={lineIdx} className="ttl-page-line">{lineEls.length > 0 ? lineEls : '\u00A0'}</p>
      })}
    </div>
  )
}
```

**字符索引与 charMap 对齐**：UTF-16 code unit 计数，`\n` 占 1 个 idx（与后端 charMap 的 `srcStart/srcEnd` 一致）。

### 3.4 前端：`TranslatedPage` 事件委托

右 cell 文字层通过 `dangerouslySetInnerHTML` 动态注入，React 不会绑事件 → 用**事件委托**：

```tsx
useEffect(() => {
  const el = cellRef.current
  if (!el) return
  const handleEnter = (e: Event) => {
    const span = (e.target as HTMLElement).closest?.('[data-src-idx]') as HTMLElement | null
    if (!span) return
    const idx = Number(span.getAttribute('data-src-idx'))
    if (Number.isFinite(idx) && idx >= 0) onHoverSrcIdx(idx)
  }
  const handleLeave = (e: Event) => {
    const span = (e.target as HTMLElement).closest?.('[data-src-idx]') as HTMLElement | null
    if (!span) return
    const related = (e as MouseEvent).relatedTarget as Node | null
    if (!related || !el.contains(related)) onHoverSrcIdx(null)
  }
  el.addEventListener('mouseover', handleEnter)
  el.addEventListener('mouseout', handleLeave)
  return () => {
    el.removeEventListener('mouseover', handleEnter)
    el.removeEventListener('mouseout', handleLeave)
  }
}, [rendered, onHoverSrcIdx])
```

**为什么用 `mouseover/mouseout` 而不是 `mouseenter/mouseleave`？**
- `mouseenter/leave` 不冒泡，无法用事件委托
- `mouseover/out` 冒泡，配合 `closest('[data-src-idx]')` 可以处理动态注入的 span

**为什么 `relatedTarget` 检查？**
- `mouseout` 在用户从父元素移到子元素时也会触发
- 用 `relatedTarget` 判断鼠标是否真的离开了整个 cell

## 7. 已知限制 / 未来优化

1. **PDF 左 cell 未做 char-level hover**：PDF 左 cell 仍是图片 + run-level 文字层（data-pdfium="4"），hover 时无响应。如需 hover 联动到 PDF，需要：
   - PDF 文字层也升级到 v5（带 charMap 的 idx）
   - 但 PDF 的 charMap 与翻译 charMap 需要在同一页内映射，复杂得多
   - **本次 v3.1 仅做纯文本任务（txt/md）的左 cell 联动**，PDF 联动留作未来增强
2. **右 cell → 右 cell 高亮未做**：因为右 cell 文字层是 dangerouslySetInnerHTML 注入的，React 不会更新 className。如需：可在事件委托里直接操作 DOM（querySelectorAll + classList）
3. **charFallback 对 ja/ko/fr/de 等质量有限**：仅做音译/转写，不保证语义正确
